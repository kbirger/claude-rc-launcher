# Command-Line Client Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `claude-rc` CLI binary that logs in through the browser and does everything the UI does, plus adds and removes hosts with a certificate pin.

**Architecture:** The hub gains a bearer-only `/cli` surface that verifies the OIDC ID token of a public client, reuses the existing `hostsApi` handlers, and adds host management on top of a new run-time `HostRegistry`. The CLI is a separate Bun program in `cli/` that talks to the identity provider directly (PKCE, no secret) and to the hub over HTTPS.

**Tech Stack:** Bun, TypeScript, Hono, jose, node:tls, node:util `parseArgs`. No new runtime dependency unless a task says so.

**Spec:** `docs/superpowers/specs/2026-11-07-cli-design.md`. Read it first. This plan only records decisions the spec leaves open.

## Global Constraints

- Tests run with `bun test server web/src cli`. Type check with `bun run typecheck` (`tsc --noEmit`). Both must pass before every commit.
- Host id regex `^[a-z0-9][a-z0-9-]{0,31}$`, and `local` is reserved. A host `url` is an `https:` origin with no path, query, fragment or credentials.
- Bearer algorithms are RS256, ES256 and EdDSA only (`createJwtVerifier` defaults). Audience is `cli_auth.oidc.client_id`.
- No secret in `[cli_auth]`, in the CLI, or in any `/cli` request body. No environment variable is read by the CLI.
- The CLI credential file and the hub state directory: file mode 600 for credentials, 644 for `pins/<id>.pem`, 700 for directories.
- Scopes: `openid email profile offline_access`. Redirect: `http://127.0.0.1:<port>/callback`. The CLI renews when the ID token has less than 60 seconds left.
- Exit codes: 0 success, 1 error, 2 not signed in or login expired.
- The binary is `claude-rc`, source in `cli/`, release targets linux x64 and arm64, darwin x64 and arm64, windows x64.
- Audit line format: `audit user=<username|sub> host=<id> <METHOD> <pathname> <status>`.
- `/cli/config` is the only open route besides `/healthz`. Host management routes exist only under `/cli/api`.
- Follow `docs/superpowers/specs/` writing style rules for documentation: short sentences, no contractions.

## Review Focus

- A browser cookie or proxy header sent to `/cli/api` gets 401, and a valid ID token sent to `/api` gets 401. Pinned by Task 6.
- A host id such as `../x`, `local`, or one already in `config.toml` is rejected before any file path is built. Pinned by Tasks 3 and 5.
- The node presents a different certificate at add time than at probe time, or is offline: nothing is saved. Pinned by Task 5.
- `managed-hosts.json` is corrupt or a pin file is missing: startup fails with a clear message. Two concurrent adds of one id: exactly one succeeds. Pinned by Task 3.
- Login callback with a wrong `state`, an `error` parameter (user denied), or a wrong nonce: login fails and the listener closes. Refresh token rejected: exit code 2. Credential file readable by group: refused. Pinned by Tasks 7 and 8.
